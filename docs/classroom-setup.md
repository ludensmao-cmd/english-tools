# Рабочие кабинеты English.tools

Проверено 8 октября 2026 года на Node.js 26.8.1 со встроенным SQLite. Дополнительные пакеты не нужны. Команды выполняются из корня репозитория, где находится `package.json`.

Это локальный сервер: он работает на этом компьютере, пока открыт терминал. Публичный сайт остаётся доступным без входа; учебные данные требуют учётной записи. Домен и доступ с других устройств пока не настроены.

## Первый запуск

1. Если учебный сервер уже запущен, остановите его сочетанием Ctrl+C в его терминале.
2. Создайте преподавателя в своём интерактивном терминале:

   ```sh
   npm run classroom:admin -- create-teacher --username teacher --name "Преподаватель"
   ```

   Логин и имя можно заменить. Введите и повторите собственный пароль: от 15 до 128 символов. Ввод скрыт. Не передавайте пароль аргументом команды, не отправляйте в чат и не сохраняйте в репозитории. Команда создаёт новую запись; существующий логин не перезаписывается.
3. Запустите сервер:

   ```sh
   npm run classroom
   ```

4. Откройте [вход](http://127.0.0.1:4174/lessons/login.html) и войдите созданным преподавателем. Публичная главная находится на [том же адресе](http://127.0.0.1:4174/).

Сервер сам создаёт пустую базу в `var/classroom/`. Примерные ученики и пароли в неё не добавляются. Статический просмотр `npm start` на 4173 продолжает работать для публичных страниц, но не обслуживает учебный API.

## Преподаватель и ученик

1. Преподаватель добавляет ученика: имя и уникальный логин. В отдельном окне появляется временный пароль; передайте его ученику лично. В списке учеников пароль не хранится и повторно не показывается.
2. Ученик входит с временным паролем, задаёт свой и входит заново. До смены временного пароля задания и файлы недоступны. Если пароль потерян, преподаватель выдаёт новый временный; прежние сессии прекращаются.
3. Преподаватель назначает занятие: ученик, тема, дата, время и продолжительность. Уровень и остаток занятий редактируются вручную; оплата и автоматическое списание не подключены.
4. В разделе домашнего задания преподаватель выбирает занятие, пишет название/описание, добавляет срок и необязательные файлы. После сохранения ученик обновляет данные и видит своё задание.
5. Ученик выбирает задание, отправляет текст и/или файлы. Преподаватель обновляет данные, выбирает конкретный ответ и сохраняет отзыв. Ученик обновляет данные, чтобы увидеть его.
6. Преподаватель завершает занятие с саммари, словами и материалами. Слова вводятся по одному на строку: `слово | значение | пример`. Ссылки: `название | https://адрес`. У ученика три пункта повторения открывают соответствующие окна последнего завершённого занятия.

Обновление данных выполняется кнопкой; уведомлений, автоматического обмена без обновления и Telegram-бота пока нет. После успешной отправки ответ нельзя редактировать и повторно сдавать в этой версии.

## Черновики и файлы

- Успех показывается после подтверждения сервера. При ошибке текст и выбор файлов остаются в открытой вкладке.
- Если сессия закончилась, откройте вход отдельно, войдите тем же пользователем, вернитесь в исходную вкладку и нажмите проверку входа. Затем отправьте форму вручную. Чужой аккаунт не отправляет старый черновик автоматически.
- Несохранённые изменения не переживают закрытие или перезагрузку вкладки. Сохранённые данные лежат в базе и доступны после нового входа.
- На один файл — до 20 МБ; до 10 файлов и 50 МБ на задание или ответ. Здесь МБ — 1 000 000 байт.
- Документы скачиваются. Превью допустимо для распознанных JPEG, PNG, GIF и WebP. HTML, SVG и остальные форматы выдаются как скачиваемые вложения.
- Загрузки хранятся вне `dist`, под случайными именами. Получение файла требует входа и прав на соответствующие записи. Не прикреплённые к записи загрузки старше суток очищаются при запуске сервера; реальные привязанные файлы сохраняются.
- Прежняя демонстрационная IndexedDB не удаляется и не импортируется в серверную базу.

## Остановка и перезапуск

Ctrl+C в терминале останавливает сервер. Повторный `npm run classroom` открывает ту же базу и загрузки. При ошибке занятого порта не останавливайте неизвестный процесс; используйте свободный локальный порт:

```sh
CLASSROOM_PORT=4176 npm run classroom
```

Откройте адрес с выбранным портом. По умолчанию сессия действует восемь часов; после восстановления из копии нужно войти заново.

## Резервная копия

Сначала остановите сервер. Команда откажется копировать данные при активной блокировке; принудительное снятие блокировки не предусмотрено. Для каждой копии используйте новую папку:

```sh
npm run classroom:backup -- backup --output backups/classroom/2026-10-08
```

Копия включает согласованный снимок SQLite и все привязанные вложения. `manifest.json` содержит размеры и SHA-256. Отсутствующий или повреждённый файл приводит к ошибке. Если выполнение прервалось, частичная папка без завершённого manifest не считается копией; повторите в другой новой папке. Действующую базу с WAL не копируйте произвольным копированием одного `.sqlite`.

После копирования снова запустите `npm run classroom`. Храните отдельную защищённую копию резервной папки на другом носителе; локальная копия на том же диске не защищает от его потери. Автоматическое расписание копий не настроено.

## Восстановление

Восстановление идёт только в новую папку, существующая не перезаписывается. Для примера обе папки ниже находятся в игнорируемом каталоге `backups/classroom`:

```sh
npm run classroom:backup -- restore --source backups/classroom/2026-10-08 --output backups/classroom/restored-2026-10-08
```

После проверки файлов и связей база восстанавливается, прежние сессии отзываются. Остановите текущий сервер и запустите восстановленные данные:

```sh
CLASSROOM_DATA_DIR=backups/classroom/restored-2026-10-08 npm run classroom
```

Войдите заново, проверьте задания, отзывы и скачайте нужные вложения. Чтобы вернуться к прежней базе, остановите этот сервер и запустите обычный `npm run classroom`. Исходная папка не изменяется. Для копирования восстановленной базы укажите тот же `CLASSROOM_DATA_DIR` в команде резервного копирования.

## Приватные данные и будущие этапы

`var/classroom/` и `backups/classroom/` целиком исключены из Git. База, загрузки, пароли, токены и личные учебные записи не должны попадать в публичный репозиторий. Если выбираете свою папку данных, храните её вне `dist` и вне публикуемых файлов. Приложение запрещает данные внутри публичного каталога.

Одна файловая база обслуживается одним процессом сервера. Несколько серверов с общей SQLite не поддерживаются. При размещении понадобятся постоянный диск, HTTPS, подходящая версия Node.js и регулярные проверяемые копии. В этой версии не подключены DBeaver, Telegram-бот, словарный API, карточки повторения и MCP; они планируются отдельно поверх созданной учебной базы.

## Проверка

```sh
npm run check:classroom
npm run check
```

Учебные проверки создают временные базы, не используют настоящих учеников и не меняют рабочую базу. Проверены отдельные учётные записи, смена и отзыв доступа, права на записи/файлы, повторы запросов, ограничения и незавершённые загрузки, полный обмен заданием/ответом/отзывом, перезапуск и восстановление копии. В браузере дополнительно проверены формы двух ролей, черновик при окончании сессии, три диалога повторения и ширины 390/1440 px. Это подтверждает локальный сценарий, не размещение сайта в интернете.
